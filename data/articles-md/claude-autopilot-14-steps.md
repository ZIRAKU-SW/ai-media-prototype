## Claude を自動操縦で動かす14ステップ ── /loop・Routines・完全オートメーション入門

月額20〜200ドルを支払って Claude を使っているのに、ChatGPT の延長のような使い方をしていませんか。ユーザーの9割は、自分がボタンを押さなくても動く自動化を一度も設定したことがないといいます。

Claude Code はここ数ヶ月で、ターミナルからクラウドまで3層の自動化スタックを静かに構築してきました。この記事では、その全体像を14ステップで解説します。

## ステップ1: /loop コマンド ── 最速のスケジュール実行

Claude Code のセッション内で `/loop` を実行するだけで、定期実行が始まります。内部では `CronCreate`、`CronList`、`CronDelete` の3つのツールが動きます。間隔は分（m）、時間（h）、日（d）で指定でき、最短は1分です。

自然言語でも指定可能です。「10分ごとにデプロイ状況をチェック」「毎朝7時にコミットを要約」のように書くだけで動きます。

![/loopコマンドの基本](https://pbs.twimg.com/media/HKD10MTW4AEX4qX.jpg)

## ステップ2: 本格的な cron 式でスケジュール設定

標準的な5フィールドの cron 式にも対応しています。ワイルドカード、ステップ（`*/15` など）、範囲、カンマ区切りが使えます。`L`（最終日）や `W`（平日）などの拡張構文には非対応です。

## ステップ3: 自動停止の4つの制約

`/loop` を使う前に知っておくべき制約があります。

- **7日で自動期限切れ**: 作成から7日後に自動削除される
- **1セッション最大50タスク**: 上限に達するまで警告は出ない
- **キャッチアップ実行なし**: 処理中に実行タイミングが来た場合、処理完了後に1回だけ実行される
- **セッション限定**: ターミナルを閉じると全キャンセル

## ステップ4: /loop と /goal の組み合わせ

`/loop` だけでは「繰り返し実行」ですが、`/goal` と組み合わせると「条件を満たすまで繰り返し改善」になります。テストのデバッグ、データ移行、受信トレイの処理など、完了条件が明確なタスクに有効です。

![/goalとの組み合わせ](https://pbs.twimg.com/media/HKDzFShXgAAhu9e.jpg)

## ステップ5: Desktop のスケジュールタスク

Claude Desktop アプリには独自のスケジューラがあります。CLI の `/loop` と違い、**マシンを再起動してもタスクが維持されます**。毎回新しいセッションとして起動するため、状態の蓄積による問題も起きません。ただし、PC がスリープ中はスキップされます。

## ステップ6: トークン予算とレートリミット

スケジュール実行のたびに1つの完全な Claude Code セッションが起動し、使用量にカウントされます。5分間隔のループを24時間回すと288セッションです。3つの対策が有効です。

- プロンプトにトークン予算を明示する（「5kトークン以内で」）
- タスクに合ったモデルを選ぶ（自動化の大半は Sonnet で十分）
- 利用量に合ったプランを選ぶ

## ステップ7: 無人実行の権限設定

デフォルトでは Claude Code は bash コマンド実行やファイル書き込みに承認を求めます。無人実行には3つの設定パターンがあります。

- `settings.json` で安全なコマンドを事前承認
- `.claudeignore` で機密ファイルへのアクセスをブロック
- 監査ログを有効化して全アクションを記録

**判断基準はシンプルです。** 「間違った場合に取り消すコストはいくらか？」安ければ自動承認、高ければ手動承認です。

## ステップ8: Auto Mode ── AI による権限分類

Auto Mode は全権限をスキップするのではなく、AI がツール呼び出しごとに「自動承認」「確認」「ブロック」を判断します。ユーザーは承認プロンプトの93%を承認しているというデータに基づき、その93%を自動化しつつ残り7%は人間に確認を求めます。

![Auto Modeの仕組み](https://pbs.twimg.com/media/HKDzlEtWAAAsn36.png)

## ステップ9: 3つのスケジューラの使い分け

| スケジューラ | 持続性 | PC が必要か | 用途 |
|---|---|---|---|
| /loop (CLI) | セッション限定 | はい | 開発中の試行錯誤 |
| Desktop タスク | 再起動後も維持 | はい（起動中） | 日常の定期タスク |
| Cloud Routines | クラウド実行 | いいえ | 本格的な自動化 |

**推奨パス**: `/loop` で動作確認 → Desktop タスクで日常運用 → Routines でクラウド化。

## ステップ10: Cloud Routines ── クラウド上での自動実行

2026年4月14日にリリースされた Routines は、**PC がオフでも Anthropic のクラウドで実行される**仕組みです。プロンプト、リポジトリ、コネクタ（Slack・Linear・GitHub など）、権限を1つのパッケージにまとめ、トリガーで起動します。

![Routinesの構成](https://pbs.twimg.com/media/HKD0OICWwAAop8z.jpg)

## ステップ11: スケジュールトリガー

最も一般的なトリガーです。毎時・毎日・平日・週次、または特定の将来時刻を設定できます。朝のブリーフィング、PR レビュー、ドキュメントの更新漏れ検出など、「毎回やるが手動だと忘れる」タスクに最適です。

## ステップ12: API トリガー

Routine に固有の HTTP エンドポイントとトークンが発行されます。CI 失敗、アラート、Webhook など、任意のシステムから Claude を呼び出せます。

## ステップ13: GitHub トリガー

PR、Push、Issue などの GitHub イベントで Routine を起動できます。コードレビュー、Issue トリアージ、CI 失敗時の原因調査と修正 PR 作成など、開発チームの定型作業を自動化します。

![GitHubトリガーの設定](https://pbs.twimg.com/media/HKD1YNqXUAAaIt0.jpg)

## ステップ14: Skills・Dynamic Workflows との連携

最後のステップでは、自動化スタック全体を統合します。

- **Skills**: 再利用可能な指示ファイルを Routine のプロンプトから呼び出す
- **Dynamic Workflows**: 並列サブエージェントが必要な複雑な自動化に
- **Routine 同士の連携**: ある Routine の出力（PR 作成、Slack 投稿など）が別の Routine のトリガーになる

完全な構成は、Skills がレシピ、Dynamic Workflows がオーケストレーション、Routines がトリガー層、Auto Mode が権限分類、監査ログが事後レビューという5層です。**すべてを初日から使う必要はありません。** `/loop` から始めて、必要に応じて上位層へ昇格させていくのが現実的です。
